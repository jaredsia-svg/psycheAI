PsycheAI in Muse: how it works

How the PsycheAI connector works: connecting, signing in, and every tool it offers.

PsycheAI · Singapore · Last updated 29 October 2026 · PsycheAI in Muse

Connecting

  • Address: https://app.psycheai.io/mcp, MCP over HTTP (Streamable HTTP, JSON replies, POST only).
  • Sign-in: OAuth 2.1 with PKCE (S256). Hosts register themselves (RFC 7591, /oauth/register); a host that asks for a client ID uses psycheai, a public client that returns only to Meta's own hosts. Discovery: /.well-known/oauth-protected-resource and /.well-known/oauth-authorization-server.
  • Accounts: the read (start, get_report_guide, publish_psyche) works without one. Sync and Psyche Pair tools answer 401 with the OAuth challenge until the user signs in: a 6-digit email code, or Google or Apple. No password, no API key.
  • Health: /health.

What a user does

  1. Start: the start tool gives any news and a four-option menu.
  2. Their read: get_report_guide gives the format (a short spec and a JSON schema); the assistant writes the read from the user's own Instagram and publishes it with publish_psyche, which returns their card image and a private psycheai.io link, valid 7 days.
  3. Sync: two people both ask (sync_with); either can then see how they sync (get_sync).
  4. Psyche Pair: the user checks their card and answers what only they can (save_profile, confirm_profile); each week, a few matches above a fixed bar (get_weekly_matches), up to 2 picks, and a mutual yes opens a private chat or an Instagram swap.

Tools

ToolTitleKindWhat it does
startStart PsycheAIReadCall this first, whenever the user connects or opens PsycheAI without saying what they want. Returns what to show them: any news, then a short menu of options to show as buttons. Read-only.
get_report_guideGet the PsycheAI guideReadThe format of the PsycheAI read the user asked for: a short specification (spec) and the JSON schema the finished read must match, for publish_psyche.
publish_psychePublish your PsycheWritesPublish the read you wrote (one JSON object following get_report_guide's schema) to psycheai.io. Returns the user's private link (valid 7 days) and their card image. If it returns problems, fix them and call again.
sync_withSync with a friendWritesAsk to sync with someone by Instagram handle, or say yes to their ask (same call). The first time it returns an ask for consent to keep the user's card: show it, and call again with consent true on Yes.
get_syncsSee your SyncsReadWho wants to sync with the user (incoming), whom they asked (sent), and their Syncs with card images.
get_syncOpen a SyncReadEverything needed to write the user's Sync with someone: PsycheAI's Sync guide, the two card-level profiles, the derived facts and the Sync card image. Write it in the chat as the guide says.
remove_syncRemove a SyncRemoves dataSay no to someone's Sync ask, take back the user's own, or end a Sync. The other side is not told.
get_pair_guideGet the Psyche Pair guideReadHow to run Psyche Pair for this user: the one message that sets it up, the matching fields, and what to do on every later visit. Call it when they say yes to Psyche Pair, and on later visits if you no longer have it.
get_instructionsGet the stepsReadThe step-by-step procedure for building this user's Psyche Pair profile. Call it first, and follow it.
save_profileSave your profileWritesSave a draft of the user's matching profile (structured fields only, never post text or quotes). Returns any issues to fix. The draft is not matched until confirm_profile.
get_my_cardSee your cardReadThe user's own Psyche Card as an image to show in the chat, and its page: how matches will see them. Works on the saved draft before confirm_profile, for the review.
confirm_profileConfirm your profileWritesThe user has read their profile and said it is right. Makes the saved draft their live profile so it can be matched. Only call after their clear yes.
set_preferencesSave who you want to meetWritesSave who the user wants to meet: their own words (brief) plus must-haves (filters) and nice-to-haves (extra points) as rules over profile fields. Read the rules back to the user before calling. Must-haves on a field the other person left empty pass. Returns the pool size the rules leave.
add_custom_questionAdd a must-have questionWritesFor a must-have the profile has no field for (e.g. "must be okay with pet reptiles"): add a yes/maybe/no question to the shared bank, or get the existing one it duplicates. Then use it in set_preferences as a must rule with field "q.<key>". Not for sex, money, race, religion, health, looks, kids, marriage, legal status or politics.
get_pending_questionsQuick questionsReadQuick questions that would sharpen this user's matches (at most 3 a week), each with fixed options. Call at the start of each visit. Show each as a question with its options as buttons, or as a short numbered list if buttons are not available. Ask openly as matching questions; never say or hint that a particular person asked.
answer_questionAnswer a questionWritesSave the user's answer to a pending question, using one of its options, or skip.
get_weekly_matchesSee this week's matchesReadThis week's matches: a few people who scored above the bar, best first, each with a photo, first name, fit % and one line on what they share. The user may pick up to 2 a week.
pick_matchPick a matchWritesThe user picks someone from this week's matches. Sends that person an intro. Uses one of the user's 2 weekly picks.
get_introsSee who picked youReadPeople who picked this user and are waiting for an answer (with a fuller card), intros the user sent, and mutual matches with their Instagram swap state (handles appear once both have offered).
respond_to_introAnswer an introWritesAnswer an intro from someone who picked the user. Yes on both sides shares Instagram handles.
share_instagramSwap InstagramWritesOffer (share: true) or withdraw (share: false) the user's Instagram to one mutual match. Handles show to both only once both have offered. Ask the user first, for each match.
make_psyche_pdfMake your PDFWritesTurn the user's full private Psyche read into a private link (valid 7 days) to a page they can read and save as a PDF. This is how the read is delivered: never paste it into the chat. We keep it only encrypted, with a key that exists only in the link.
send_messageSend a messageWritesSend a message in the private chat with a mutual match (no contact details shared). Under 1000 characters. Send exactly what the user wrote.
get_messagesRead messagesReadWith introId: the private chat with that match, to show the user word for word. Without: which matches have unread messages.
end_chatEnd a chatRemoves dataEnd the private chat with a match (for example once they have swapped numbers). Deletes the messages.
log_dateLog a dateWritesAfter a date with a mutual match: did they meet, and would they see them again (yes/maybe/no). Only these answers are saved; any reflection stays in this chat.
block_or_reportBlock or reportWritesBlock someone so neither sees the other again, optionally reporting them with a reason. A report on a match you chat with keeps that chat for our safety team to review.
pause_matchingPause matchingWritesPause or resume being matched (paused people get no drops and appear in none).
delete_my_dataDelete your dataRemoves dataPermanently delete everything PsycheAI keeps about the user: their card, profile, preferences, matches, intros, chats and Syncs. Confirm with the user first.

Every tool carries MCP's hints: reads are read-only, and only removing things is destructive.
